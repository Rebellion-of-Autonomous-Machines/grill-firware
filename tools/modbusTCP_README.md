# modbusTCP гриля: протокол версии 3

В версии 3 счётчики наработки передаются в целых часах вместо секунд версии 2.
Адреса сохранены. Карта несовместима с версией 1. Прошивку и Python-клиент обновлять вместе.
Сохранённые настройки термостата и высоты продолжают использоваться.

W5500: CS GPIO5, IP по умолчанию 192.168.1.51, TCP порт 502, Unit ID 1.
Настройки Ethernet доступны в веб-интерфейсе.

В таблицах «адрес» означает нулевое смещение в пакете.
40001 соответствует Holding адресу 0; 30001 соответствует Input адресу 0.
Функции: 03 чтение Holding, 04 чтение Input, 06 запись одного Holding,
10 (hex) запись нескольких Holding. Пробелы в карте не читаются как нули.

## Holding Registers: команды и настройки

| Номер | Адрес | Доступ | Значение |
|---|---|---|---|
| 40001 | 0 | RW | Stat_Mode: запись 11 открыть, 12 закрыть |
| 40002 | 1 | RO | Stat_Error: 0 нет ошибки, 1 ошибка датчика, 2 перегрев |
| 40003–40006 | 2–5 | запрещён | Man_Control: любое чтение/запись возвращает исключение 03 |
| 40007 | 6 | запрещён | Man_Time: любое чтение/запись возвращает исключение 03 |
| 40008 | 7 | RW | TARGET_X10: уставка °C ×10, int16, 100...3000 |
| 40009 | 8 | RW | CLOSING_HEIGHT_MM: высота 0...180 мм, по умолчанию 60 |
| 40010 | 9 | RW | HEATING_ENABLE: 0 выключить, 1 разрешить термостат |
| 40011 | 10 | RW | HYSTERESIS_X10: гистерезис °C ×10, 5...500 |
| 40012 | 11 | RW | MIN_ON_SECONDS: 0...3600 с |
| 40013 | 12 | RW | MIN_OFF_SECONDS: 0...3600 с |
| 40014 | 13 | RW | EMERGENCY_X10: порог аварии °C ×10, от уставки до 3000 |
| 40015 | 14 | RW | ANTICIPATION_ENABLE: 0/1 |
| 40016 | 15 | RW | Сервисная команда: 1 нагрев ВКЛ, 2 ВЫКЛ, 5 сброс ошибки, 6 сохранить настройки |
| 40017 | 16 | RO | COMMAND_RESULT: 0 успешно, 1 неизвестная команда, 2 занят, 3 неверный параметр |
| 40018 | 17 | RO | PROTOCOL_VERSION = 3 |

При чтении Stat_Mode: 11 открывается, 12 закрывается, 1 готов к закрытию,
19 завершено закрытие / ожидается открытие, 99 ошибка датчика или перегрев.
Во время движения отображается 11/12; ошибка одновременно доступна в 40002.
Запись состояний 1/19/20/30/99 запрещена. Ручного режима и команды STOP нет.
Сервисный регистр после команды читается как 0.
Ошибки сбрасываются только отдельной командой 5, не записью состояния.
Нагрев сохраняет прежнее поведение термостата, таймера нагрева нет.

Числовые настройки ограничиваются прошивкой допустимым диапазоном; поля
веба и Python проверяются до отправки. Для разрешения нагрева и упреждения
принимаются только 0/1. Высота передаётся uint16, отрицательные значения запрещены клиентом.
Текущую принятую настройку следует проверять чтением.

## Input Registers: телеметрия

| Номер | Адрес | Значение |
|---|---|---|
| 30001–30002 | 0–1 | Общая наработка, uint32 часов |
| 30003–30004 | 2–3 | Наработка включённого контактора ТЭНа, uint32 часов |
| 30021 | 20 | Аварийный DI6: 0 разомкнут, 1 замкнут на землю |
| 30051–30056 | 50–55 | Команды выходам реле 1–6, 0/1 |
| 30071 | 70 | Температура °C ×10, int16; 0x8000 нет данных |
| 30072 | 71 | Напряжение AD8495, мВ |
| 30073 | 72 | Ошибка датчика, 0/1 |

Счётчики: старшее 16-битное слово первым, значение уже в часах, без масштабирования.
Передаются полные часы: 59 минут = 0, 90 минут = 1.
Внутренний учёт и сохранение в NVS остаются в миллисекундах, чтобы сохранять
остаток неполного часа и накопленные данные предыдущей прошивки.
Сохраняются совместно в NVS раз в 60 секунд; при внезапном отключении питания
теряется до последней минуты. Значения на проводе насыщаются на UINT32_MAX.
Состояния реле показывают команды выходам, а не обратную связь контактов.
У гриля один аварийный DI6; подтверждения достижения положения по концевикам нет.

Для Python и диагностики предусмотрен непрерывный снимок:

| Номер | Адрес | Значение |
|---|---|---|
| 30081 | 80 | STATUS_BITS: bit0 нагрев разрешён, bit1 контактор, bit3 перегрев, bit4 датчик, bit5 DI6 |
| 30082 | 81 | TEMPERATURE_X10 |
| 30083 | 82 | TARGET_X10 |
| 30084 | 83 | HYSTERESIS_X10 |
| 30085 | 84 | MIN_ON_SECONDS |
| 30086 | 85 | MIN_OFF_SECONDS |
| 30087 | 86 | EMERGENCY_X10 |
| 30088 | 87 | 0, резерв |
| 30089 | 88 | COMMAND_RESULT |
| 30090 | 89 | RELAY_LOCK_SECONDS |
| 30091 | 90 | FAULT_CODE, как 40002 |
| 30092 | 91 | HEATING_ENABLE |
| 30093 | 92 | SENSOR_MV |

| 30095 | 94 | Осталось открытия, с |
| 30096 | 95 | ANTICIPATION_ENABLE |
| 30097 | 96 | Скорость температуры, °C/мин ×100, int16 |
| 30098 | 97 | Порог включения °C ×10 |
| 30099 | 98 | Порог выключения °C ×10 |

| 30108 | 107 | Состояние сценария, как 40001 |

Все Input Registers только для чтения. Настройки в снимке являются копиями
Holding Registers, а не отдельными настройками.

## Движение и DI6

После включения выполняется открытие на 6 секунд, затем запускаются интерфейсы.
Команда 11 открывает на 6 секунд, команда 12 закрывает до заданной высоты по времени.
Высота 0...180 мм, максимум закрытия 2,4 с; для 60 мм примерно 1,31 с.
Общий кубический полином построен по таблице; высота является расчётной,
а не показанием датчика положения.

Пока мотор работает, команды движения из любых интерфейсов отклоняются.
Нагрев, настройки и чтение состояния остаются доступны.
После открытия разрешено закрытие, после закрытия разрешено только открытие.
Регистр следующего направления не отменяет блокировку во время движения.

DI6 имеет приоритет: фронт замыкания на землю прерывает движение и запускает
полные 6 секунд открытия. При новом срабатывании во время открытия таймер
перезапускается. Удержание DI6 не перезапускает таймер бесконечно.
При переключении реле сохраняется защитная пауза 120 мс.
Нагрев DI6 не выключает. Пока DI6 активен, закрытие запрещено.
После аварийного открытия цикл ожидает закрытие после освобождения DI6.

## Исключения и пакетная запись

02 — неизвестный адрес / запись RO; 03 — запрещённый Man_Control/Man_Time,
неподдерживаемая команда или неверное значение 0/1; 06 — движение занято,
стартовое открытие или нарушение чередования/DI6.
Ошибки протокола не подменяют Stat_Error (состояние оборудования).

Перед записью 10 проверяется весь пакет. Если внутри есть запрещённый/RO
регистр либо недопустимая команда, никакие значения из пакета не применяются.
Запрос чтения, пересекающий запрещённые адреса, также отклоняется целиком.
Нельзя читать 40001...40018 одним запросом: используйте 40001–40002 и 40008–40018.
Команды 7/8 старой версии больше не управляют движением.

Пример: записать 60 в Holding адрес 8, затем 12 в адрес 0 для закрытия.
После завершения записать 11 в адрес 0 для открытия.
Включить нагрев: записать 1 в адрес 9 либо команду 1 в адрес 15.

## Термостат с упреждением

Настройки по умолчанию: уставка **100 °C**, гистерезис **2 °C**, минимальное время
ON/OFF **10/10 с**, аварийная температура **300 °C**, упреждение включено.
При первом запуске новой версии сохраненный гистерезис **5 °C** однократно
заменяется на **2 °C**. Отличающееся от 5 °C сохраненное значение, уставка,
времена ON/OFF и аварийный порог сохраняются. После миграции можно снова
установить 5 °C, последующие перезагрузки его не изменят.

Это по-прежнему термостат с контактором на реле 4, не ПИД и не ШИМ.
При росте температуры он отключает нагрев раньше уставки с учетом текущей
скорости роста; при остывании включает раньше нижнего порога. Минимальное
время состояния контактора имеет приоритет над обычным переключением.
При выключенном упреждении действует прежний алгоритм: OFF при уставке,
ON при `уставка - гистерезис`. Гистерезис не означает гарантированную
точность ±2 °C.

Начальные оценки упреждения: 30 с для выключения и 15 с для включения.
Поправка порога ограничена 10 °C при выключении и 5 °C при включении;
включение при температуре не ниже уставки запрещено. После упреждающего
выключения контроллер ожидает окончания остаточного роста, прежде чем
снова включать нагрев в этой зоне.

Тренд рассчитывается каждые 2 с по отфильтрованным измерениям, с дополнительным
сглаживанием скорости (постоянная 4 с). После переключения отслеживается
максимум/минимум температуры. Для подстройки требуется разворот минимум
на 0,3 °C, подтвержденный тремя последовательными измерениями тренда.
Оценка обновляется на 25% расхождения, не более 10 с за этап, в пределах
0...120 с. Прерванные этапы, пропуски измерений более 5 с, скачки более
1 °C/с и этапы дольше 180 с не используются.

При движении крышки обучение приостанавливается. Изменение уставки,
переключение режима нагрева или упреждения сбрасывает оценки. Они хранятся
только в ОЗУ и не изнашивают flash повторными записями.

Ручное выключение, ошибка датчика и аварийная температура отключают контактор
без ожидания минимального времени ON. Аварийный порог проверяется также по
температуре до сглаживания. Если последнее измерение старше 3 с, проверка
регулятора отключает контактор; это программная проверка в основном цикле,
не независимая аппаратная защита от зависания.

В веб-интерфейсе показаны расчетные пороги, скорость температуры и число
этапов подстройки. Пороги динамические: состояние контактора дополнительно
зависит от блокировки ON/OFF и ожидания остаточного роста. Параметр запроса
`/thermostat/set` `anticipation=0/1` необязательный, старые запросы сохраняют
текущий режим.

После прошивки сравните несколько полных циклов при одинаковой загрузке
и положении крышки. Уменьшение колебаний может увеличить число переключений;
допустимую частоту нужно сверить с характеристиками своего контактора.
Калибровка AD8495 не изменена: стабильность регулирования не подтверждает
абсолютную точность измерений.

### Проверки без оборудования

`test/thermostat_anticipation_test.cpp` проверяет упреждение, ограничение порогов,
обучение, шум, пропуски и переполнение времени. Простая тепловая модель
сравнивает новый алгоритм с прежним гистерезисом 5 °C при одинаковых ON/OFF 10 с
и задержках 10, 30 и 60 с. Это синтетическая проверка, не измерение гриля.

`test/controller_safety_test.ps1` извлекает функции управления из текущего
`src/main.cpp` и проверяет их на хосте с подменой времени и релейного выхода.
Требуется настольный компилятор `g++` (не компилятор Xtensa из PlatformIO).

```powershell
g++ -std=c++11 -Wall -Wextra -pedantic -I include test/thermostat_anticipation_test.cpp -o .pio/thermostat_anticipation_test.exe
./.pio/thermostat_anticipation_test.exe
./test/controller_safety_test.ps1 -Compiler g++
./test/motor_stop_disabled_test.ps1 -Compiler g++
./test/modbusTCP_protocol_test.ps1 -Compiler g++
platformio run
```

## Tkinter тестер Modbus TCP

Файл: `tools/modbusTCP_tester.py`

Нужна прошивка с картой версии 3. Тестер проверяет версию в 40018,
читает Input Registers 30081...30108 и счётчики 30001...30004.
Параметры подключения прежние: IP контроллера, порт 502, Unit ID 1.
Изменение IP/порта/Unit ID применяется после повторного подключения.

- Флажок **«Упреждение и автоподстройка»** сразу записывает 0/1 в Holding Register 40015 (адрес 14)
  и проверяет результат обратным чтением. Нажимать «Записать термостат» для
  флажка не нужно. Если подтверждение не получено, показывается ошибка.
- Отдельно показаны разрешение нагрева, состояние контактора и оставшаяся
  блокировка переключения. Они не равнозначны: разрешенный нагрев не означает
  постоянно включенный контактор.
- Диагностика показывает расчетные пороги, скорость в °C/мин, упреждение
  включения/выключения в секундах и число завершенных этапов подстройки.
  Автоподстройка непрерывная, поэтому процента готовности нет. Надпись о паузе
  выводится по состоянию нагрева, аварии и движения крышки, а не по отдельному
  регистру фазы обучения.
- График показывает реальные последние 60 минут: зеленая температура,
  оранжевая сглаженная линия, красная уставка, синий пунктир включения и
  серый пунктир выключения. Сглаживание в Python влияет только на график,
  не на регулирование. Расчетные пороги берутся из контроллера, а не
  пересчитываются в приложении.
- Под графиком находится полоса контактора: желтый означает ВКЛ, серый
  ВЫКЛ, пустой участок отсутствие данных. Разрывы связи не соединяются
  вымышленными линиями. Это история опросов, а не журнал каждого физического
  переключения контактора.
- Начало накопления находится справа, у отметки «сейчас»; график заполняется
  в течение часа. При переподключении к тому же устройству история остается,
  при смене устройства очищается.
- Измененные поля сохраняют ввод до успешной записи, даже при переходе фокуса
  в другое поле. Для дробных значений поддерживаются точка и запятая.
- При потере связи текущий статус помечается как неизвестный, а не сохраняется
  как якобы актуальный. Выключение нагрева остается доступным для попытки команды,
  если TCP-клиент еще подключен. Ручной остановки привода нет.

Установка:
```bash
pip install pymodbus
```

Запуск:
```bash
python tools/modbusTCP_tester.py
```

Проверки интерфейса с имитацией Modbus, без подключения к грилю:
```bash
python -B -m unittest discover -s test -p test_tkinter_thermostat.py -v
```
